# X-批注 v1.0.0

同时支持 AutoCAD 与 ZWCAD 的本地批注插件，无需登录或联网。两种宿主共用同一套源码、DWG 数据格式、界面和命令。

> **来源声明**  
> 本插件由「爱德华hehe」的 **GM批注** 修改而来，感谢「爱德华hehe」的无私奉献。
>
> **与 GM批注 的关系（两份可同机共存）**
>
> | 项            | 原版 GM批注                  | 本版 X-批注                                   |
> | ------------ | ------------------------ | ----------------------------------------- |
> | 界面名称         | GM批注                     | X-批注                                      |
> | 命令前缀         | `GM_PZ_*`                | `X_PZ_*`                                  |
> | 命名空间 / 程序集   | `GMAnnotation`           | `XAnnotation`（`XAnnotation.AutoCAD*.dll`） |
> | 数据目录         | `%APPDATA%\GMAnnotation` | `%APPDATA%\XAnnotation`                   |
> | 自动加载注册表键     | `GMAnnotation`           | `XAnnotation`（**不会**去动原版的键）               |
> | 编号前缀 / 默认图层名 | `GM-001` / `GM-批注`       | `X-001` / `X-批注`                          |
>
> 首次运行时会把原版 `%APPDATA%\GMAnnotation` 里的设置 / 历史 / 图号记忆**复制**一份过来  
> （只复制、不删除、不覆盖，原版一切照旧）；想从干净配置起步，删掉 `%APPDATA%\XAnnotation` 即可。
>
> **图纸内的数据标识刻意沿用原值**：XData 应用名 `LA_PZ_ANNOTATION`、命名组前缀 `LA_PZ_NOTE_`、数据键 `LA_PZ_DATA`。  
> 因此本版本可以直接识别、编辑、增补**原版画在图纸里的批注** —— 换成新前缀反而会让旧图批注全部失联。  
> （原版自己从更早的 LA 品牌改名到 GM 时，同样没有动这几个标识。）

## 安装与加载

### 1. 获取 DLL

从 GitHub Releases 下载 `XAnnotation-v0.5.2.zip` 并完整解压，再按 CAD 宿主选择 DLL：

| CAD 宿主             | DLL                                             |
| ------------------ | ----------------------------------------------- |
| AutoCAD 2012~2014  | `bin-acad2012/XAnnotation.AutoCAD2012.dll`      |
| AutoCAD 2015~2024  | `bin-acad/XAnnotation.AutoCAD.dll`              |
| AutoCAD 2025~2027  | `bin-acad2025-2027/XAnnotation.AutoCAD2025.dll` |
| 中望 ZWCAD 2025~2026 | `bin/XAnnotation.ZWCAD.dll`                     |

**注意**：四个 DLL 不可混用，请严格按 CAD 宿主和版本选择；DLL 同目录内的依赖文件也必须保留。

> **为什么 2012~2014 要单独一个 DLL**：AutoCAD 2013 的 "The Big Split" 是 .NET API 的二进制兼容断点  
> —— API 实现从 `acad.exe` 迁到 `AcCore.dll`、声明从 `acmgd.dll` 迁到 `accoremgd.dll`，  
> 并且 `Autodesk.AutoCAD.ApplicationServices.Core` 命名空间从 2013 才存在。  
> 因此针对 2013+ 编译的程序集在 2012 上**加载不了**，2012 必须对着它自己的 `acdbmgd.dll` / `acmgd.dll` 编译。

### 2. 加载插件

在 CAD 命令行执行：

```
NETLOAD
```

在弹出的文件对话框中选中对应的 DLL。

### 3. 安装自动加载（可选）

首次 NETLOAD 后，在菜单栏 **X-批注 → 安装自动加载** 点击一次即可。之后每次启动该 CAD，插件会自动加载。再次点击该菜单项可关闭自动加载。

> 原理：在当前用户注册表中写入启动加载项。ZWCAD 与 AutoCAD 各自独立配置。

## 快速上手

### 画第一条批注

1. 点击 CAD 工具栏 **X-批注** 上的单字键 **批**（或菜单 **X-批注 → 批注绘制**，或命令行输入 `X_PZ_NOTE`）
2. 功能选择框弹出：**这时面板是"待命"状态，还没有抢 CAD 命令**，所以可以慢慢勾选 连续绘制 / 多对一台注 / 仅绘云线、改外形、改专业/批注人
3. **把鼠标移回图纸**（或按 **回车**、或直接点一个外形按钮）→ 按"当前外形 + 当前选项"立刻开始
4. 按当前外形取范围：**矩形**＝拖两个角点框选（云线外形取自「批注设置」里的矩形/菱形/椭圆）；**PL线**＝在图上逐点画出折线（回车结束，至少 3 点）；**基点**＝点一个基点
5. **弹出批注内容窗口 → 填写内容 → 确定**
6. 云线（基点外形时是引线）即时预览，**移动鼠标定位文字框**（框内显示真实批注文字，框体尺寸按内容算好，所见即最终效果）→ **点击确认位置**
7. 完成！云线（基点外形没有云线）、文字、边框、引线会组成一个编组同时落图。

> **为什么不是"打开即开始"**：CAD 命令一旦挂起取点提示（拖拽/选点），鼠标输入就被 CAD 独占，  
> 面板上的勾选框和按钮**点不动**。早先"打开面板即自动开始"正好把面板冻住，于是出现  
> "打开后先勾多对一 / 仅绘云线没反应，必须先跑完一轮"的怪象。现在改成"待命 → 回图纸开始"，  
> 上面的第 2 步因此完全有效。  
> 启动方式任选：**光标移回图纸**（默认路径，一次点击都不用）／**点一下图纸**／**按回车**／**点任意外形按钮**。  
> 若误触发了（比如本来只想缩放图纸却把光标停在图纸上），按 **Esc** 取消本轮，再回面板改就行。  
> 按 **Esc** 退出批注对话框（面板有键盘焦点时生效；正在画会连带取消这一轮交互）。  
> 当前外形用**蓝色底**标识。**面板会记住上次的选择**：外形（矩形 / PL线 / 基点）与 连续绘制 / 多对一 / 仅绘云线  
> 四个勾选项，下次打开面板自动恢复上次的状态；只有「批注设置」里的完整参数才另存。  
> 这些"上次选择"**不会**写进 `CloudOnly` / `ContinuousAnnotation` 这些"本轮快照"字段，所以**不影响 快 键的快速直绘**。  
> **未勾选「连续绘制」时，画完一条批注就自动退出**（回到 AutoCAD，不再连续要下一处）；勾上才会接着画下一处。  
> **「仅绘云线」优先于「多对一」**：勾上仅绘云线会自动取消多对一，两者同时勾选按仅绘云线走。  
> **「多对一」只适用于「矩形」外形**；选 **PL线 / 基点** 会自动取消「多对一」（它们是单区域绘制），  
> 选 **基点** 还会取消「仅绘云线」（基点批注本来就不画云线）。  
> 单字键 **批** 打开功能选择框；**快** 是不弹框的快速直绘。  
> 工具栏 **快** 键 / 菜单 **快速直绘**（`X_PZ_DRAW`）：按当前设置直接框选绘制，不做任何选择。

### 知识库条目（规范条文表）

页面里第一列是**序号**（按文件顺序从 1 编号，仅供定位；导出时重排、导入时忽略），业务列为  
**专业 / 属性 / 规范名称 / 规范编号 / 条款 / 内容**。表格**可直接编辑**，改完自动保存，不需要点"保存"按钮。

- **导出CSV**：列序与列表完全一致（`序号,专业,属性,规范名称,规范编号,条款,内容`），**导出的文件就是导入模板**——在 Excel 里改完另存为「CSV UTF-8」再导回即可。
- **导入CSV**：表头按名称识别（兼容 `规范名 / 标准名称 / 规范号 / 文件编号 / 条款号 / 条文内容 / 批注内容` 等别名，也容忍空格与 `*`）；**表头识别不到时按上面的顺序逐列解析**。判重规则是 **规范编号 + 条款相同即视为同一条**（更新），两者都空则一律新增；清单里已有的其它条目不会被删掉。
- **编码**：按 UTF-8(BOM) → UTF-8 → GBK → 系统默认 依次尝试，所以 Excel 直接"另存为 CSV"（GBK）也能读，但中文环境更稳的是另存为「CSV UTF-8」。
- **备份**：删除选中 / 清空 / 导入之前都会把整个知识库原样备份到 `%APPDATA%\XAnnotation\knowledge.json.bak`（只保留最近一次）；表格里直接改这种常规保存不备份。
- **常用批注语导入**：第一行含「常用批注语 / 批注内容 / 内容」表头时取该列，否则取第一列逐行读入，同内容不重复添加。

> 批注窗口的「立即入库」勾选只会写「专业 + 内容」两列（规范名称/编号/条款留空，之后再手工补），与在知识库里直接导入/手工编辑是两条互不冲突的入口。

### 增补云线（一条批注，多个范围）

一条批注需要圈出图上多处位置时用 `X_PZ_ADDCLOUD`：点选一条既有批注后，连续框选新范围，每框一次就补画一条云线 + 一条从云线连到**原文字框**的引线，回车/空格结束。

**新补的云线＝原批注的外形 + 批注设置里的云线样式/半径**（含比例换算与自适应），图层、颜色、线宽仍照抄原批注：

| 复制项         | 来源                                                           |
| ----------- | ------------------------------------------------------------ |
| 图层          | 原云线所在图层（原批注图层带日期/人名后缀时也照抄，不会落到"今天"的图层上）                      |
| 颜色 / 线宽     | 原云线、原引线实体上的实际值（引线粗细单独取，不跟云线混）                                |
| **外形**      | **原批注的外形**（矩形/菱形/椭圆按云线实体反推；反推不出来时照抄原云线顶点模板），**不是**"批注设置"里的外形 |
| 云线样式 / 弧瓣大小 | 批注设置「外形与云线」页的当前设置（等宽/渐变）                                     |

> 早先"新补的云线外形取当前设置"，于是从菱形/椭圆批注上增补出来的却是矩形（默认设置就是矩形）。  
> 现在外形一律跟着原批注走，选点预览与落图同口径——**预览里看到什么形状，落图就是什么形状**。  
> **反推外形的算法**：把云线包围盒归一化后看每个顶点的"极径剖面"，分别与矩形 / 菱形 / 椭圆的理论剖面比误差，  
> 取误差最小且小于容差（10%）的那个。云线顶点严格落在轮廓上（生成时只改弧瓣、不移点），所以能精确判定；  
> 判定不出（例如 PL 线的任意多边形）就走顶点模板照抄。一共三级兜底：  
> **① 反推出矩形/菱形/椭圆 → 按该外形重建；② 反推不出但原云线是普通多段线 → 照抄原顶点模板；③ 原批注是「基点」批注（根本没有云线）→ 才退回"批注设置"里的外形。**  
> 日志（`Logs\XAnnotation.log`）里会记下实际探测到的外形和是否走了兜底，排查时直接看它。  
> 另一个入口：**编辑批注窗口的「增补云线」按钮**（点「编」打开面板后可见）——窗口先保存已填内容并关闭，在图上连续框选增补（回车结束），随后自动重开窗口继续编辑，已填内容不丢。

### 导入到其他 DWG 保持原样式

导出 CSV 会带 5 列图面实测尺寸（**图面字高 / 图面首行字高 / 图面次行字高 / 图面云线半径 / 图面线宽**）；导入到其他 DWG 时按编号新建的批注会**逐条照抄这些实测值**（比例置 1、关自适应、字高弧瓣线宽用实测值），样式与原图保持一致，不会按本机当前设置重算。旧版 CSV 没有这几列也能正常导入（按当前设置生成，历史行为）。

### 导出保留图形坐标 / 导入按原坐标还原

导出 CSV 还带 **8 列放置信息**：**布局 / 云线X1 / 云线Y1 / 云线X2 / 云线Y2 / 文字X / 文字Y / 标高**（全部为 WCS 绝对坐标；云线两角点是云线**顶点**的包络，不含向外鼓出的弧瓣，所以反复导出导入不会越还原越大；文字锚点是文字框左下角，也就是创建时传入的锚点）。

导入时：

- 带坐标的条目（本版导出的 CSV）**默认按原图坐标还原**——连同**布局**一起还原（模型空间的回模型空间，某布局的回该布局；本图没有这个布局时落到当前空间并在报告里提示），落在与原图完全相同的位置，不需要再指定基点；
- 只有一部分行带坐标时，命令行会问 `新建批注位置 [按原图坐标(P)/指定基点(B)] <P>`；
- 没有坐标的行（旧版 CSV、手工编辑删掉了坐标列）仍走老流程：指定基点 → 网格排布；
- 已经存在同编号批注的行只**更新信息、保留图上位置**，不会被坐标搬动。

> 坐标与"图面实测尺寸"配合，才能做到导到别的图纸后**位置 + 样式**都与原图一致。

### 合并批注与按内容过滤

这两件事都&#x4EE5;**「批注内容完全一致」**&#x4E3A;准（换行归一、去首尾空白后逐字符相等；**日期/批注人/编号不参与判重**——编号本来就各不相同，一旦参与就永远合并不了）。

**合并（`X_PZ_MERGE` / 工具栏「合」/ 过滤窗口里的按钮）**

1. 先弹确认框，列出检测到的分组（`编号 × 内容摘要`）与将保留/并入的条数；
2. 每组保留**编号最小、且有编组**的那条作主批注；
3. 其余批注的**云线与引线整体并入**主编组（等于把重复的批注变成"一条批注、多个范围"，与"多对一批注"同构）；
   - 引线**指向文字框的那一端**改接到主批注文字框最近的角点（先看它离原文字框更近的是哪端）；
   - 云线/引线的**图层、颜色、线宽统一照抄主批注**——图层名带日期/人名后缀，不统一的话按图层隐藏会漏掉一半实体；
   - 跨布局（模型空间/图纸空间）的批注**不合并**，会在报告里说明；
4. 重复批注的**文字与文字框删除**，编组解散；
5. 留痕：主批注记一条"合并"，被并入的每条记一条"合并删除"。整个操作支持 UNDO。

**过滤（`X_PZ_FILTER` / 工具栏「滤」）**

- 打开「批注过滤」窗口：按内容分组列出`条数 / 编号 / 内容摘要`，选中一行点「仅显示所选」（或双击该行）→ 图中**只显示这一组**，其余批注全部隐藏；点「显示全部」恢复。
- 窗口里也能直接点「合并批注」，合并后列表自动刷新。
- 若执行命令前**已选中**一条批注，会直接按它的内容过滤，并把对应分组选中。
- 只切**实体可见性**（与隐藏/显示同一机制），不删数据、不改图层；注意「显示全部」会把之前手动隐藏的批注也一起显示出来。

### 批注内容可以为空

**内容不是必填项** —— 只填编号（编号仍必填）也能生成批注，适合"先把位置和范围圈出来、内容回头再补"的用法。  
**「批注：」这一行始终显示**：有内容就是「批注：xxx」，没内容就是「批注：」——这样图上一眼能看出  
"这条批注还没写内容"，而不是整行凭空消失。编号照常保留用于列表 / 导出 / 导入匹配；  
之后双击这条批注（或 `X_PZ_EDIT`）把内容补上即可。

> 注意：**合并批注（`X_PZ_MERGE` / 过滤窗口）会跳过空内容的批注**，否则一堆"都还没写内容"的批注会因为  
> "内容完全一致（都是空）"被整批误合并掉。

### 批注内容输入建议

批注窗口的内容输入框带实时建议（勾选框「输入建议」控制，默认开，选择会被记住）：

- **语料**：① 批注历史记录里以前写过的批注内容（`history.json`）② 知识库「常用批注语」③ 知识库「规范条文条目」的正文；条目还能按规范名称/编号/条款检索（输入 `GB50007` 或 `地基基础` 也能找到对应条文）。
- **每条候选都带来源标签**（历史 / 常用语 / 条目），条目还显示"规范名称 编号 条款"。
- **匹配规则**：候选以当前已输入内容**开头** → 排最前，套用即"续写"；否则按包含关系与字词重合度排序。候选在**当前行**里匹配，套用时**只替换当前行光标之前那段**，其它行不动。
- **操作**：↑↓ 选择 · 回车 / Tab 套用 · Esc 关闭 · `Ctrl+空格` 手动调出 · 鼠标点击也可套用。正在写长句（当前行超过 14 字且没有可续写候选）时不会弹窗打扰。
- **完全本地**：不联网、不调用任何模型，只做关键词级检索与排序，不会凭空生成新句子；本行没有合适的候选时就安静地不显示，手写完全不受影响。

> 语料改动（知识库/历史）最多 2 秒后反映到候选里；同一文件在 1 秒内按 2 秒窗口读一次，逐键输入不会反复读盘。

## 批注类型

### 矩形（默认，＝跟随「批注设置」里的云线外形）

拖拽两个角点确定云线范围；**云线外形取自「批注设置 → 外形与云线 → 云线外形」**：  
设置里选 **矩形 / 菱形 / 椭圆**，功能选择框选「矩形」画出来的就是对应形状  
（面板上的「矩形」＝"按设置来"，而不是"画矩形"）。


### PL 线（自定义闭合折线）

在功能选择框把外形切到「PL线」，再把光标移回图纸：连续点击折线顶点，**至少 3 个不同、不共线、不自交的点**，  
达到 3 点后按回车/空格完成，Esc 取消。可画出任意闭合多边形云线（最多 400 个折点）。

云线沿该折线生成；**引线接在该自定义云线轮廓上**（取轮廓上离文字框最近的点），不会像包围盒那样脱开。  
PL 线是单区域绘制，「多对一」会被自动取消；「仅绘云线」「连续绘制」都可用。

> **取折点期间会自动关掉对象捕捉与正交**（与「矩形」拖角点完全同口径，取自设置里「行为 → 自动关闭正交/捕捉」，  
> 两项默认都是开）：不关的话 CAD 会把鼠标点下去的位置自动吸附到附近已有对象上，  
> 拿不到"点哪儿就是哪儿"的折点，云线轮廓也跟着走样；关掉之后，**点下去的位置就是折点位置**。  
> 想沿既有图形的节点描轮廓（例如贴着墙线描一圈），把设置&#x91CC;**「自动关闭正交/捕捉」取消勾选**即可恢复捕捉。  
> 两个系统变量都是在取点前后临时置 0 / 原样恢复，**不动用户自己的 CAD 设置**。

> 逐点拖拽的预览是**平滑**的：与视图方向有关的计算（云线弧瓣朝向）只在进入第一步时算一次，  
> 之后每帧只做纯几何绘制，**拖拽期间不访问数据库和编辑器**。这是 Jig 的硬性要求，  
> 违反会让 AutoCAD 丢弃整帧预览（表现为卡顿/闪烁/预览时有时无）。详见下方"已知问题规避"。  
> 折点提示的返回值可能为空（用户在这一步按 Esc 或由 Jig 自行取消时 `Editor.Drag` 返回 `null`），  
> 代码已按"先看 Jig 自己的结束/中止标志、再判返回值"处理，不会抛异常。

### 基点（不画云线）

在功能选择框把外形切到「基点」，再把光标移回图纸：

1. 在图上点一个**基点**（引线的起点，可捕捉）→ **点上之后立刻在原地画出基点标识**，先看清基点落在哪儿
2. 填写批注内容（此时标识仍在图上，可以边填边核对位置）
3. 拖动批注文本框定位 → **点击确认**

落图＝**基点标识 + 基点 → 文字框的一条直线 + 文字 + 文字框**，**没有云线**（引线另一端取离基点最近的框角）。  
这是"指到哪儿说哪儿"的引线式批注，适合给某个点/某个设备挂一条说明。  
字号自适应用"当前视图高度的 20%"当参照（没有云线范围可量），未开自适应时仍按"打印字高 × 出图比例"算。

> **基点标识**：在基点位置画一个「**圆环 + 穿心十字**」标记（圆环由两段半圆弧拼成，十字臂长出圆环约 0.45 倍半径），  
> 让基点在图上一眼可辨、也能正常打印。这个画法参照 CAD 制图惯例里的原点/中心标记  
> （AutoCAD 自带的 `CENTERMARK`、公差体系的 datum target 十字指示符号）。  
> 标记半径 = `max(正文字高, 文本框高 × 0.18)`，所以字高或框大时标记跟着变大，不会小到看不见。  
> 它作为独立实体按 XData 角色 `marker` 加入同一个批注编组，随批注一起移动/删除/格式刷/合并。
>
> **"点完先看见位置"是怎么做的**：点完基点后**马上在图上画一份临时标识**（这一步还不知道文字框多高，  
> 先按正文字高估个尺寸），你在填内容时就能确认位置对不对；内容窗口一关就把它擦掉，接着拖放定位时  
> 由放置预览按**最终尺寸**重画同一个符号，中间不会出现空档。取消流程也会被擦掉，不会在图上留垃圾。

### 多对一批注

在功能选择框（工具栏 **批** 键 / 菜单 **X-批注 → 批注绘制**）中勾选"多对一批注"（外形须为「矩形」），再把光标移回图纸即开始：

1. 连续绘制 **2 个及以上** 云线范围（与矩形的两角点方式相同；不足 2 个时会提示继续指定）
2. 每个云线完成后立即显示在图上
3. 在下一个区域的第一个角点提示时 **按回车/空格** 结束区域选择
4. 统一填写内容、定位文字框
5. 所有云线共用同一组文字和编号，每条均有独立引线（与「增补云线」后的效果一致）

> 外形为 **菱形 / 椭圆** 时，每条引线的起点取**该云线轮廓**上离文字框最近的点，不是包围盒角点  
> （菱形/椭圆的包围盒四角根本不在轮廓上，取角点会让引线头悬空、与云线脱开）；矩形仍取包围盒角点。  
> 「仅绘云线」**优先于**「多对一」：勾上仅绘云线会自动取消多对一，两个同时勾选时按仅绘云线走。

## 功能选择框与设置

### 功能选择框（工具栏「批」键 / 菜单「批注绘制」弹出）

| 功能项   | 说明                                                                                                                                |
| ----- | --------------------------------------------------------------------------------------------------------------------------------- |
| 批注外形  | **矩形 / PL线 / 基点** 三个按钮：点一下即把该外形设为当前项（**蓝色底**）**并按它开始这一轮**；**记住上次选中项**，下次打开面板自动恢复                                                  |
| 连续绘制  | 勾选后一处批注完成即自动开始下一处，无需再选命令；**不勾则画完一条就自动退出**。**记住上次勾选状态**（下次打开面板恢复）                                                                  |
| 多对一批注 | 勾选后先连续选 2 个及以上范围，再统一填一段文字（等效「增补云线」效果）。**只适用于「矩形」外形**；选 PL线/基点会自动取消它。**记住上次勾选状态**                                                  |
| 仅绘云线  | 只画云线，不生成文字、边框和引线。**优先于「多对一」**：勾选它会把多对一取消掉，两者同时勾选按仅绘云线走。**记住上次勾选状态**；但它只写进面板专属字段，**不影响工具栏「快」键的快速直绘**。**「基点」外形下会自动取消**（那种外形本来就不画云线） |
| 批注设置… | 打开「批注设置」窗口（**非模态**：与面板各自独立，可同时操作、各自拖动/关闭、点谁谁在前；新窗口默认摆在面板右侧）                                                                       |

> **三种外形各是什么**：  
> **矩形** ＝ 按「批注设置」里选的云线外形（矩形/菱形/椭圆）拖两角点框选——面板上写「矩形」是"按设置来"的意思；  
> **PL线** ＝ 在图上逐点画出闭合折线，云线沿这个自定义形状生成（单区域）；  
> **基点** ＝ 只点一个基点，引线从基点直连到批注文本框，**不画云线**（单区域）。

> **操作顺序：面板打开后先"待命"，勾好选项再回图纸开始。**  
> 启动方式任选：**把光标移回图纸**（默认路径，一次点击都不用）／**点一下图纸**／**按回车**／**点任意外形按钮**。  
> **为什么不做"打开即开始"**：CAD 命令一挂起取点提示就独占鼠标，面板上的控件点不动 ——  
> 那样会导致"打开后先勾多对一 / 仅绘云线没反应，必须先跑完一轮"（详见下方"已知问题规避"）。  
> 误触发了（例如本来只想缩放图纸）按 **Esc** 取消本轮，回面板改完再来。  
> **Esc** 关闭批注对话框（面板有键盘焦点时生效；若正在画，会连带取消这一轮交互）。  
> 面板待命期间改选项只是更新状态，**不会**立刻抢 CAD 命令行。  
> 窗口高度按内容自适应，内容不再需要滚动；屏幕太矮时会自动出现滚动条。  
> 外形用按钮而非单选钮，是因为 AutoCAD 宿主下点击 RadioButton 会触发致命错误（见下方"已知问题规避"）。  
> 面板只保留「批注外形」「绘制方式」两个小标题，**标题下不放任何操作说明文字**。

### 「批注设置」窗口与面板的关系（非模态、互不干扰）

点面板底部的 **批注设置…** 会打开设置窗口，它是**非模态**的：

| 行为          | 说明                                                    |
| ----------- | ----------------------------------------------------- |
| 独立移动 / 独立关闭 | 两个窗口各拖各的、各关各的；**关面板不会把设置窗口一起关掉**（反之亦然）                |
| 点谁谁在前       | 鼠标点哪个窗口，那个窗口自动升到最上层，不用先关掉另一个                          |
| 初始位置        | 新打开时摆在功能选择框**右侧**（面板固定在屏幕左上角），两个窗口同时可见；之后你再拖到哪儿它就留在哪儿 |
| 单实例         | 重复点"批注设置…"只是把已开的那个调到前面，不会开出一堆                         |

> **实现要点**：两个窗口都是宿主里的置顶窗口（否则用户回图纸画一笔，窗口就沉到 CAD 后面看不见了）。  
> 两个 Topmost 窗口相互之间不会自动让位，所以在 `Activated` 时用 `SetWindowPos(HWND_TOPMOST)`  
> 把当前这个顶到置顶组最上层（`WpfWindowUtil.BringToTop`）。  
> **不能靠"模态"来管**：模态会禁用其它顶层窗口，这正是原先"设置窗口一开，面板既点不动、  
> 也不能单独关、必须先退出设置窗口"的根因（`ShowModalWindow` → 改为 `CadDialog.ShowModeless`）。  
> 另外：两个窗口共用**同一个**设置对象（`SettingsWindow.SharedSettings()`），  
> 面板在设置窗口还开着时重开也会沿用它那一份 —— 各持一份的话，谁的落盘都会把对方刚改的值覆盖回去。  
> 设置窗口开着期间，面板的"光标移回图纸即开始"这条入口会临时关掉（用户是在配置，不是在画；  
> 设置窗口压着的正好是图纸，鼠标划过它就容易莫名开始一轮），设置窗口一关就自动恢复。  
> 同理，弹**模态**窗口（批注内容窗、格式刷等）之前，会把其它置顶窗口临时降为普通窗口  
> （`CadDialog.LowerTopmostWindows`），免得模态窗口躲在它们后面。

### 本次参数（选择框内可调）

| 设置项    | 说明                                                                       |
| ------ | ------------------------------------------------------------------------ |
| 专业     | 下拉选择或自行输入                                                                |
| 批注人    | 默认为当前 Windows 用户名                                                        |
| 云线样式   | 等宽（均匀弧瓣）/ 渐变（手绘：弧瓣宽度自起点 0 起单调增大，最大值＝2×云线半径；轮廓线带手绘起伏，幅度＝云线半径。云线线宽只决定描边粗细） |
| 角色     | 批注人 / 校审人 / 回复人                                                          |
| 自动编号   | 开启后按 X-001、X-002… 自动递增                                                   |
| 允许双击编辑 | 是否允许双击批注直接进入编辑                                                           |

> **关键规则**：面板上的**外形**与**连续绘制 / 多对一 / 仅绘云线**这几个"上次选择"会**记住并自动恢复**（下次打开面板就是上次的状态）；  
> 它们存在面板专属字段 `PanelShape` / `PanelContinuous` / `PanelMultiMode` / `PanelCloudOnly` 里，  
> **刻意与 `CloudOnly` / `ContinuousAnnotation` 分开** —— 后两者是"本轮绘制快照"，而工具栏 **快** 键（`X_PZ_DRAW`）读的是同一份  
> `settings.xml`，混写会让快速直绘被面板的勾选污染。除此之外的"本次参数"仍会持久化到设置文件。  
> **面板打开后处于"待命"**：不启动任何 CAD 命令，勾选项/外形/参数随便改；把光标移回图纸（或点图纸 / 回车 / 点外形）才真正开始。  
> 命令一跑起来鼠标就被 CAD 独占，面板这时点不动 —— 所以"边画边改选项"不可靠，请在开始前改好。  
> 范围已定型（填内容 / 定位批注框）之后再改，则留待下一轮或按新选项重开本轮。  
> 只想改一下选择就走人？**直接关面板也会记下**（`Closing` 里会保存一次面板选择）。

### 完整设置（"批注设置…"按钮）

| 分类     | 设置项                                                                                                                                                                         |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 云线     | **云线外形**（矩形/菱形/椭圆；功能选择框选「矩形」时按它画）、半径(mm)、线宽(mm)、**云线自适应**（默认勾选）                                                                                                             |

| 颜色     | 统一颜色 / 分项颜色（云线、引线、文字、框、对勾）；另有独立的 **状态颜色（整条批注）** 区块                                                                                                                          |

| 人员     | 默认批注人、默认专业、默认角色                                                                                                                                                             |
| 行为     | 自动关闭正交/捕捉、双击编辑、指北规则、自动编号、连续批注                                                                                                                                               |

设置保存在 `%APPDATA%\XAnnotation\settings.xml`，全局生效。

> **状态颜色（整条批注）** —— 「已回复」/「已完成」各给一个颜色，勾上「按状态给整条批注着色」，效果是：  
> 这条批注的**云线、文字、边框、引线、基点标识全部一起改成那个颜色**（是"一个颜色管整条批注"，  
> 不是逐个元素设色）；状态改回「待处理」时再按各元素的基础色恢复。  
> 状态是在编辑批注窗口里选（或 CSV 导入时带进来的），所以**在编辑窗口把状态一改，整条批注当场换色**。  
> 这两项**与"统一颜色"互不相干**：统一颜色管"各元素是否同色"，状态颜色管"整条批注要不要按状态换色"，  
> 所以勾着统一颜色也照样能设状态色（保存时不会被统一颜色覆盖掉）。  
> 改完颜色想让**已有批注**也跟着变，运行一次 `X_PZ_REFRESH`（按当前设置刷新全图批注）即可；  
> 格式刷（`X_PZ_FORMAT`）也会**保留**目标批注的状态色，不会把"已回复"的黄色刷回普通色。

> **自适应默认勾选**：`云线自适应` 与 `字体自适应` 从 v2 起默认开启。老配置（无 `<SchemaVersion>` 节点）在首次读取时  
> 会被**一次性**打开这两个开关——历史上"从下拉里选比例就自动取消自适应"会把它俩写成 `false`，让人误以为默认没勾。  
> 现在选比例**不再**静默取消自适应；两者同时有效时以自适应为准，是否改用比例由你自己决定（只有在本次打开设置窗口  
> 里确实动过比例下拉、保存时才问一次）。用户手动取消勾选后会被正常记住。

## 杂项

- **双击编辑**：双击批注的云线、引线、文字或边框即可编辑。实现分两步：先用**双击点坐标 + 系统变量 `PICKBOX`** 做拾取框命中测试确定"到底点中了哪条批注"（不依赖预选集，编组内实体也不会失手），再**拦下 CAD 的原生双击命令**（例如双击文字的 `MTEDIT`、双击多段线的特性面板）后启动插件自己的编辑；编辑期间临时抑制快捷特性，结束后恢复用户原设置。若宿主环境异常，可直接用 `X_PZ_EDIT`

- **数据存储**：批注数据和编号记录在 DWG 文件的 Group 扩展字典中，COPY 后 UUID 暂不自动重新编号
- **本机数据文件**（`%APPDATA%\XAnnotation\`）：`settings.xml` 设置 · `history.json` **批注历史记录**（留痕）· `knowledge.json` **知识库**（规范条文条目 + 常用批注语）· `drawingnos.json` 图号记忆 · `recentcontents.cleared` "历史下拉"的清除标记。其中**批注历史记录与知识库是两套独立体系**：各自的查询、导出、删除、清空互不影响

## 已知问题规避（改动时请勿踩回去）

以下几条都是**宿主环境限制**，不是普通编码疏忽，改 UI / 预览时容易误踩：

- **不要在 AutoCAD 插件窗口里用 `RadioButton`**。点击 AutoCAD 宿主中的单选钮会进入  
  `System.Windows.Controls.RadioButton.UpdateRadioButtonGroup()` 并直接导致**致命错误**（进程崩溃）。  
  已由 AutoCAD 崩溃转储的 CLR 调用栈确认，与生成何种几何无关。  
  功能选择框的"批注外形"因此用 **Button**（点击即开始，当前外形用蓝色底标识）。
- **「基点」批注的编组里没有 `cloud` 实体**（只有 text / box / leader）。所有按 XData 角色遍历编组的  
  地方都必须容忍"没有云线"：增补云线、导出坐标、合并、格式刷、移动、编辑……都已确认可以缺云线运行；  
  新增这类遍历逻辑时不要再假设 `role == "cloud"` 一定存在。反过来，这类批注也**不能**用几何反推外形  
  （`ProbeExistingStyle` 会返回 `Shape == null`），此时增补云线退回"批注设置"里的外形。
- **增补云线的外形一律照原批注**（`AnnotationService.BuildAppendCloud`：先按云线实体反推矩形/菱形/椭圆，  
  反推不出来再照抄原云线顶点模板），**不要再改回"读当前设置里的外形"** —— 那会让菱形/椭圆批注增补出矩形，  
  而且预览（`AppendCloudStyle`）与落图会不一致。
- **★ CAD 命令挂起取点提示期间，插件的 WPF 面板是"点不动"的 —— 别把"面板里改选项立即生效"当成可靠机制**。  
  CAD 在执行取点/拖拽提示时独占鼠标输入（面板收不到点击），所以那段窗口里 `CheckBox`、`Button`、  
  `DispatcherTimer` 都指望不上。早先"打开面板即自动开始绘制"正好把面板冻在这样的窗口里，  
  表现就是 *打开面板后先勾「多对一批注」/「仅绘云线」没反应，必须先跑完一轮才生效*（连续三轮都栽在这）。  
  **现行做法：面板打开后先"待命"，不启动任何 CAD 命令**，等用户把光标移回图纸 / 点图纸 / 按回车 /  
  点外形按钮时才启动（`AnnotationPanel.StartByTrigger` + `OnStartDelayTick`）。  
  因此：**任何"面板一打开就进入命令上下文"的改动都会把这个 bug 带回来**。  
  待命期的触发入口：① 光标移回图纸（`Editor.PointMonitor`，只在 AutoCAD 宿主挂载，  
  ZWCAD 分支留空实现）；② 面板失活且此时的前景窗口就是 **CAD 主窗口**  
  （`IsCadMainWindowForeground`：先比 `Process.MainWindowHandle`，拿不到再退回"同进程 + 排除本插件自己的 WPF 窗口"，  
  否则点开「批注设置…」会被误判成"回到图纸"而擅自起一轮）；③ 回车 / 点外形按钮。
- **Jig 的 `WorldDraw` 里用 `Geometry.Polygon` 填充时，必须先把实体颜色写进 `SubEntityTraits`**。  
  `Geometry.Draw(entity)` 会带实体自身颜色，而 `Geometry.Polygon` 是"裸"几何基元，**只认  
  `SubEntityTraits.Color`**；不显式赋值，拖拽预览中的云线/引线就会被画成当前色，与落图后的批注颜色不一致。  
  见 `AnnotationJigs.cs` 的 `RegionPreviewDrawing.ApplyColorToTraits`。
- **宽多段线在 `WorldDraw` 里不出带宽**：世界绘制对多段线只按中心线出图，不参与 `ConstantWidth` /  
  顶点宽度的带状渲染，所以预览会"淡显"。须由 `DrawWidePolyline` 逐段展开成小凸多边形填充。  
  注意**不能把整条云线沿法向偏移成一个闭合环**——云线是锯齿状，环必然严重自交、完全填不出来。
- **Jig 的 `WorldDraw` 里绝对不能访问数据库 / 编辑器**（`Document`、`Editor`、`Transaction`、`GetCurrentView()`…）。  
  它是逐帧回调，在里面读数据库会与拖拽期间的回滚刷新打架，AutoCAD 会**整帧丢弃**该次预览 ——  
  症状是"这一步预览一个都不显示，但流程照常走完"，或者"拖拽卡顿/闪烁"。  
  与光标无关的几何（含"云线弧瓣朝哪边"这种依赖视图方向的判断）**必须在 Jig 构造函数里算完**并缓存成字段：  
  `CloudBulgeSign(doc, normal)` 进构造函数，`WorldDraw` 只调纯几何的 `OrientCloudBulges(cloud, sign)`。  
  改动预览代码后请 grep 一遍 `GetCurrentView` / `Editor` / `Document`，确保没有残留的逐帧调用。
- **`Editor.Drag(jig)` 在 Jig 自己从 `Sampler` 返回 `SamplerStatus.Cancel` 时会返回 `null`**，而不是返回一个带  
  `Status = Cancel` 的 `PromptResult`。所以取点的收尾必须**先看 Jig 自己的标志（`FinishRequested` / `Aborted` /  
  `HasSample`），再判返回值是否为空**，否则会抛 `NullReferenceException`（PL 线逐点提示曾因此报错，  
  但因为异常被包在提示内部，表现为"报错但仍能继续画"）。`AnnotationService.InteractionResult.From` 已做判空。
- **面板的"上次选择"字段不要与 `CloudOnly` / `ContinuousAnnotation` 混写**。后两者是"本轮绘制快照"，  
  而工具栏 **快** 键（`X_PZ_DRAW`）读的是同一份 `settings.xml`；把面板勾选写进去会让快速直绘被面板污染。  
  面板选择一律走 `PanelShape` / `PanelContinuous` / `PanelMultiMode` / `PanelCloudOnly`，  
  并且 `ApplyPanelSettings()` 落盘前仍显式置 `_s.CloudOnly = false; _s.ContinuousAnnotation = false;`  
  **外形也不写回 `_s.Shape`**（`FinalizeAnnotation` 的 `Save(_s)` 会连累快速直绘）。
- **状态色只能从 `StatusColorOverride(settings, status)` 这一个入口取**（再由 `CloudColorFor` /  
  `BoxColorFor` / `LeaderColorFor` / `TextColorFor` 转发给各元素）。不要在新加的创建/更新路径里  
  直接读 `settings.ReplyColor` / `settings.PassColor`：那样"改一次状态色就把整条批注所有元素都改掉"  
  的约定会在那条路径上悄悄失效（旧代码就是只改文字颜色，所以图上会出现"云线还是原来的色、只有文字变色"）。  
  另外 `SettingsWindow` 保存时**不要把 `ReplyColor` / `PassColor` 卷进"统一颜色"的同步赋值**，  
  否则用户挑的状态色会在保存瞬间被冲成统一色。
- **`DrawTemporaryBasePointMarker` 画的临时基点标识必须擦掉**（`EraseTemporaryEntities`）。  
  它没有 XData、也不在任何编组里，**不会被识别成批注实体** —— 忘记擦就是图纸上的永久垃圾，  
  而且会和 `CreateBasePoint` 生成的正式标识重在一起。擦除放在 `finally` 里，取消/异常路径都要走到。  
  之所以用真实实体而不是 `TransientManager`：临时图形要按视口逐个登记、视图一变还得重画，  
  而且要给 ZWCAD 分支引一整套 `GraphicsInterface` 别名（本机没有 ZWCAD 程序集，编不过也就验不了）。
- **不要在提示挂起时靠 `SendStringToExecute("\x1b")` 中止本轮交互**。它是"排进命令行"的，  
  提示没结束就不保证被及时消费，于是"改选项 → 没反应"；更要命的是那个 Esc 可能**晚到**，  
  把紧接着自动重开的新一轮一起取消掉。正确做法是插件内协作：置 `InteractionAbort`，  
  由我方 Jig 在 `Sampler` 里检查后 `SamplerStatus.Cancel`，第一角点也不能再用 `Editor.GetPoint`  
  （黑盒，无法中止），改用 `FirstCornerPromptJig`。
- **插件自己的浮动窗口之间：非模态 + 置顶 + "点谁谁在前"，不要用模态来管彼此的关系**。  
  模态（CAD 原生 `ShowModalWindow` 或 WPF `ShowDialog`）会**禁用其它顶层窗口**，于是  
  "批注设置窗口一开，批注面板既点不动、也不能单独关，必须先退出设置窗口"（用户报的 bug 就是这么来的）。  
  改成非模态（`CadDialog.ShowModeless`）后两个窗口各拖各的、各关各的。  
  又因为浮动窗口都必须是 `Topmost`（否则用户回图纸画一笔，窗口就沉到 CAD 后面看不见了），  
  而两个 Topmost 窗口相互之间**不会**自动让位，所以要在 `Activated` 里主动  
  `SetWindowPos(HWND_TOPMOST)` 顶到置顶组最上层（`WpfWindowUtil.BringToTop`）。  
  **不要改用"`Activated` 置 `Topmost=true` / `Deactivated` 置 `false`"那套**：那会让窗口在用户回图纸时也沉下去。  
  也不要写 `IsCancel` / `IsDefault`：那是"对话框"语义，非模态窗口下给 `DialogResult` 赋值会抛异常，  
  Esc / 回车要自己在 `PreviewKeyDown` 里收（见 `SettingsWindow.Window_PreviewKeyDown`）。
- **弹模态窗口（批注内容窗 / 格式刷 / 关于）之前，先把其它置顶窗口临时降为普通窗口**  
  （`CadDialog.LowerTopmostWindows` + `RestoreTopmost`）。否则模态窗口会躲在它们后面 —— 典型症状是  
  "设置窗口还开着时开始画批注，批注内容窗好像没弹出来"，其实是被置顶的设置窗口盖住了。模态结束后原样恢复置顶。  
  候选窗口来自两处：各漂浮窗口构造时登记的 `CadDialog.RegisterFloating`（弱引用表，不依赖 `Application.Current`）  
  ＋ 能拿到时再并上 `Application.Current.Windows`。
- **批注面板与批注设置窗口必须共用同一个 `AnnotationSettings` 对象**（`SettingsWindow.SharedSettings()`：  
  设置窗口开着就沿用它那份，否则才 `SettingsStore.Load()`）。两边各持一份时，  
  任何一边的"落盘"都会把另一边刚改的值覆盖回去（例如在设置里把云线外形改成椭圆，  
  随后从面板开始画一轮，面板落盘时又写回旧值）。
- **设置窗口开着期间，面板的"光标移回图纸即开始"入口要临时关掉**（`SettingsWindow.IsOpen` 判定，  
  见 `Activated` / `OnPanelLoaded`）：用户是在配置不是在画，而设置窗口压着的正好是图纸，  
  鼠标划过它就可能莫名其妙开始一轮。设置窗口一关（`Closed`）自动恢复这条入口。  
  标志的生命周期严格限定在"被中止的那一轮"内：`StartAnnotation` 开头与 `finally` 各 `Clear()` 一次。  
  （注：这套机制只在"面板还能收到事件"时才有机会生效 —— 见上一条，正常路径已经不再依赖它。）

## 已知限制

- COPY 会复制批注 UUID，尚未自动重新编号
- 暂不提供 Excel 导出和图片批注
- **AutoCAD 2012~2014 目标（`net40`）需要 AutoCAD 2012 的 `acdbmgd.dll` / `acmgd.dll` 才能编译**：这两条 API 不在 NuGet 上（`AutoCAD.NET` 包最老只到 20.0.0 = AutoCAD 2015）。安装 AutoCAD 2012 后直接 `build.cmd 2012` 即可，也可只把那两个 DLL 拷到任意目录再用 `-p:Acad2012Dir="该目录"` 指定
- 该目标需要宿主目录放一份 `System.ValueTuple.dll`（`AnnotationService` 用了命名元组返回值），`build.cmd release` 会自动带上
- 目标机若是 AutoCAD 2013/2014 **且只装了 .NET 4.0**，也需要用 `net40` 产物；装了 .NET 4.5 及以上则可直接用 `net45` 产物
